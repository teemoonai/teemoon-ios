## Added

**Images**
- You can attach photos from the library, take one with the camera, or paste one. "+" opens an attach sheet on every model (`teemoon/Views/Chat/AttachSheet.swift`, `teemoon/Views/Chat/ImagePickers.swift`).
- Paste paths are the edit menu's Paste, hardware ⌘V and the keyboard bar's photo suggestion. They work because the composer field is now a UIKit text view (`teemoon/Views/Chat/ComposerTextView.swift`, `teemoon/Views/Chat/ComposerText.swift`).
  - The field stays plain text, and a Genmoji becomes its text description.
  - A pasted item that offers an image attaches the image and drops the item's text.
  - A lone `data:` image URL pasted into the field becomes an image.
  - The pasteboard is read only when a URL is pasted, never for plain words (`teemoon/Chat/Images/PastedImage.swift`).
- Decoding (`teemoon/Chat/Images/ImageIntake.swift`):
  - JPEG, PNG and GIF (first frame only) are decoded by Wuffs. Wuffs is vendored source; see Dependencies.
  - HEIC/HEIF, WebP, AVIF, TIFF and BMP that arrive by paste or share are decoded by Apple ImageIO (`teemoon/Chat/Images/SystemImageDecode.swift`) and then go through the same pixel path.
  - The photo picker asks Photos for a JPEG or PNG copy, which then goes to Wuffs. The camera hands over pixels.
  - A paste reads the pasteboard's own bytes, so an app that offers only a `UIImage` still attaches.
  - The on-device path's ImageIO resize (768 px) only ever reads teemoon's own re-encoded JPEG, never received bytes.
- Every image is turned upright, scaled to at most 2048 px on its long side, and re-encoded with no metadata, so location and camera details are dropped.
- Input limits are 20 MiB encoded, 50 MP, and 16,384 px per side (`ImageIntake.swift:20-22`).
- New SwiftData model `ImageAttachment` in `TeemoonSchemaV2`. Deleting a message deletes its images. SwiftData's external image files beside the store get the store's file protection and backup exclusion, at launch and after each image save.
- Images are sent as OpenAI-style `image_url` parts, and only to a model that takes images. Limits per request:
  - Cloud models: up to 10 images and 8 MiB of image data (`ChatViewModel.cloudImagesPerSend`, `teemoon/Inference/ChatGeneration+Transcript.swift:26-27`).
  - Images from earlier turns are re-sent with the history, within those limits.
- On a model that can't read images, a paste or a pick still attaches. At send the app refuses, with three choices: "choose model", "send text only" or "cancel" (`teemoon/Presentation/ImageRefusalAlert.swift`, `teemoon/Presentation/ImageModelChoice.swift`).
- Phone models read images: see "On-device (Gemma / LiteRT-LM)" below.
  - A model on the user's own Ollama machine gets one `/api/show` capability check (4 s timeout) before a photo is refused, unless it was checked in the last hour (`teemoon/Providers/HomeCapabilityRefresh.swift`).
- In the chat, a sent message shows at most 4 images in a 2×2 grid. From the 5th image on, the 4th tile reads "+N" (`teemoon/Chat/Images/MessageImageGrid.swift`).
- A tapped image opens with a zoom from its thumbnail. Long-pressing an image offers copy, save to Photos and share (`teemoon/Chat/Images/ImageActions.swift`). This adds `NSPhotoLibraryAddUsageDescription` and `NSCameraUsageDescription` to `teemoon/Info.plist`.
- Composer thumbnail row (`teemoon/Views/Chat/ChatComposer.swift`, `teemoon/Chat/Images/ComposerImages.swift`, `teemoon/Presentation/ComposerImageMachine.swift`):
  - The attached images sit above the text in 64 × 64 pt thumbnails (`teemoon/Views/Chat/ThumbnailImage.swift`).
  - Each thumbnail has a remove "×" with a 44 × 44 pt hit area and the accessibility label "remove image". A removed image animates away, and the row folds when the last image goes.
  - A photo that is still loading shows a placeholder tile with a small grey spinner. The photo fades in over the tile. Send stays disabled until every photo has loaded, and loading tiles never outnumber the free slots.
  - Over the image limit, every image is kept, send is refused, and the limit note shows.
  - The images leave the composer on the same frame as the text when sent.
- The attach sheet ("+"): "take photo" and "choose photos" as large buttons, plus a footnote. On a model that can't see images, it says so and offers the where sheet, filtered to models that read images. Pulling the sheet up doesn't grow it to full screen.
- The request details card lists each image's size, and how many earlier images a request left out and why.
- In the where sheet:
  - Models that read images are marked with a muted eye.
  - A "show only" row filters by "reads images" and "end-to-end encrypted" (`teemoon/Views/Where/WhereShowOnlyRow.swift`, `teemoon/Presentation/WhereFilterPolicy.swift`). The filters also apply in the model browser and in the provider form.

**On-device (Gemma / LiteRT-LM)**

The engine version is unchanged at LiteRT-LM v0.17.1 (see Dependencies). Changes since 1.0.6:

- Images to Gemma on the phone are on (`LocalModelCatalog.imagesOnDevice = true`, `teemoon/Providers/LocalModelCatalog.swift:157`).
  - Before an image reaches LiteRT, the stored JPEG is re-encoded at 768 px on its long side (Gemma's own preprocessing size), JPEG quality 0.85 (`teemoon/Inference/OnDeviceImage.swift`).
  - The engine is created with a vision budget of 280 tokens per image.
- Memory checks (`teemoon/Inference/PhoneImageMemory.swift`) use the memory an image turn needs, as measured on an iPhone 16 Pro:
  - Gemma 4 E2B needs 2,980 MB and takes up to 10 images per message.
  - Gemma 4 E4B needs 3,510 MB and takes up to 4.
  - Any other phone model never reads images.
- **At launch**, the app reads the most memory it could ever have, once: currently available memory plus its own footprint (`ceilingMB`).
  - A model whose need is above that is permanently refused for images: "this phone doesn't have enough memory for images with <model>." The where sheet lists it under "reads images" with that caption, but it isn't counted.
  - The E4B download is not offered under the "reads images" filter on a phone where it can't fit.
- **On send**, the app compares free memory with the model's need (`PhoneImageMemory.turn`, called from `teemoon/Inference/ChatGeneration.swift:377`).
  - If memory is short right now, the turn isn't run. The message reads "<model> needs about N GB free for images; this phone has M GB free right now. close some apps and try again."
  - The refusal offers a smaller model that fits, when there is one.
- **Kill memory** (`PhoneImageMemory.KillStore`):
  - A mark is set in UserDefaults before an image turn and cleared after it, and also when the app goes to the background.
  - A mark still present at the next launch (`settleAfterLaunch`, `teemoon/App/teemoonApp.swift:51`) means the OS killed that turn. That model is then refused for images on this phone, and the turn is never retried automatically.
- Phone turns re-send the chat's earlier images, as cloud turns do, within the model's per-message number and the memory check. The composer's image cap follows the phone model (`ChatViewModel.swift:37`).
- **Tool calls**: LiteRT-LM patch 9 stamps each tool call with its conversation's id, and `LiteRTToolBridge` runs only calls from the current turn's own conversation. A decode the app had abandoned can no longer start a web search under the next turn.
  - The output cap and a drain timeout count as "cut short", not as interruptions.
  - A stopped turn's tool call runs nothing.
  - An engine that finishes after an eviction is ignored.
- **Web search tool**: with no Brave key, the web_search offer sends only `query`. With a key but the web chip off, no tool is sent.
- **Caches**: LiteRT's caches moved from the purgeable `tmp/` to `<model>/litert-cache`. They are deleted with the model, and stale ones are swept.
- **Load line**: the chip shows the engine's load line while the model loads (`teemoon/Inference/EngineLoadLine.swift`, conformance `loading.json`).
- **First paragraph**: a phone reply's first paragraph is not held (`StreamReveal.onDeviceFirstHoldMs = 0`).
- `LocalLanguageModel`'s 0.7 temperature was removed, since it never reached LiteRT.
- The bench log line no longer reports LiteRT's own time-to-first-token, which stays at turn 1 when a conversation is reused.
- "may not fit" for a phone model now reads the phone's RAM floor, not free memory. This is the download-time hint; the image-turn checks above use free memory.

**Share extension**
- New target `teemoonShare` (`teemoonShare/`, bundle id `$(SHARE_APP_BUNDLE_ID).share`, deployment target iOS 18.6). It copies shared photos and text into an app-group inbox and opens teemoon (`teemoon/Support/ShareInbox.swift`, `teemoon/Support/ShareJump.swift`, `teemoonShare/ShareViewController.swift`).
  - Shared items open in a new chat's composer. Nothing is sent until the user sends it.
  - Caps: 10 images, 20 MiB per image, 100,000 characters of text. When more is shared, the newest share wins.
  - The extension has the app-group entitlement only. It has no keychain group and makes no network calls.
  - Inbox items are written with `completeUnlessOpen` protection and excluded from backup. Items older than 7 days are removed at app launch, before each write, and before each take.
- New entitlement `com.apple.security.application-groups` (`group.$(PRODUCT_BUNDLE_IDENTIFIER)`) on the app and on the extension.
- New URL scheme `$(PRODUCT_BUNDLE_IDENTIFIER)`, used by the extension to open the app.

**near.ai Private Chat import**
- The import is at settings → chats → "import from near.ai". It runs as its own sheet, with steps, a confirm step that shows counts, progress, and a summary (`teemoon/Views/Settings/NearImportView.swift`, `teemoon/Views/Settings/ChatImportResultView.swift`).
  - There are separate result screens for nothing new and for an empty file.
  - After "done" or "show chats", it offers to delete the export file.
- A near.ai export can also be opened from Files or the share sheet. Files in iCloud are downloaded first. `CFBundleDocumentTypes` registers `public.json` as a Viewer with rank Alternate, and `LSSupportsOpeningDocumentsInPlace` is set.
- Parser (`teemoon/Chat/Import/`):
  - `ImportFileScanner` is a streaming scanner. An element over 64 MiB is skipped without parsing, and nesting depth is capped at 64.
  - `NearImportSource` maps near.ai's format, and `ChatImportWriter` writes the chats whatever their source.
- Images:
  - Images embedded as `data:` URLs in JPEG, PNG or GIF become attachments, up to 10 per message.
  - Images the export only links to are never downloaded. The summary counts them, and the message reads "[image not imported]".
- Handling of the export file:
  - A file shared into teemoon is moved out of `Documents/Inbox` into `Caches/ImportStaging` when it arrives, and is excluded from backup.
  - If Settings closes, a flow opened from outside is not reset. After a reset, a late dry run or import writes nothing.

**Reply lifecycle**
- `teemoon/Chat/ReplyMachine.swift` models a reply's lifecycle as a pure type with no SwiftData, and the send path is wired through it.
- Every reply row records how its turn ended. `TeemoonSchemaV3` adds two optional, lightweight fields: `Message.statusRaw` (nil means complete) and `Message.sentBeforeConfirmed`.
- A stopped, cut-short or unfinished reply says so ("you stopped this reply.", "this reply was cut short.", "this reply didn't finish."), and the line is still there when the chat is reopened. "retry" is offered on the newest unfinished reply.
- An unsent retry changes nothing on disk until its request goes out. It never destroys a reply that has content.
- A message sent before the attestation verdicts settled is marked as such (`teemoon/Confidential/SentBeforeConfirmed.swift`). The mark resolves once that record's own verdicts settle.

**Trust and verification**
- `teemoon/Confidential/VerdictDeadline.swift`: the near.ai tier check gives up after 20 s, and every check ends in a verdict. A timed-out check asks before sending, titled "teemoon couldn't confirm near.ai's hardware", with "send anyway" and "don't send". The tier list is fetched without a key.
- `teemoon/Confidential/TrustScope.swift`, `ActionLogBinding.swift`, `ActionLogReading.swift` and `RunningPairCheck.swift` build one trust scope per attestation record from the GPU node's report as served.
  - Every compose file that the attested action log names as running is hash-checked.
  - A binding mismatch is a hard break, which blocks the send. An unchecked binding asks.
  - New rows on the expert trust screen show this.
- `teemoon/Confidential/LauncherIndex.swift` looks up the launcher's multi-platform index on Docker Hub and checks its Sigstore attestation against near.ai's `compose-manager` build workflow.
  - A rate-limited or failing lookup is inconclusive, never "unpublished", and inconclusive asks.
  - New keyless hosts: `auth.docker.io` and `registry-1.docker.io`.
- `teemoon/Confidential/QuoteChecks.swift` adds checks on each model node's quote:
  - A debug TD quote is evidence against the node.
  - An advertised `report_data` that is not the quote's own is evidence against it.
  - `mr_config` must commit to the compose the node served.
  - A node that sent no GPU evidence reads "couldn't check", never verified.
- `teemoon/Confidential/ChatPath.swift` judges a chat by the services its requests pass through, with liveness tracked per service.
- The self-verification script shown in the app now also finds and checks the launcher's index on Docker Hub.

**Other**
- Developer mode can set the reasoning level per model on the model detail page (`teemoon/Inference/ReasoningLevel.swift`).
  - The levels come from the model's own list or from the request control: effort low/medium/high; OpenRouter's list plus low; off/on for a thinking switch or a phone model.
  - The where chip shows "<model> <level>", and a reasoning bar in the where sheet links to the levels (`teemoon/Views/Where/WhereReasoningBar.swift`).
  - A refused level reads "model's default", and the footer says that the setting is left out.
  - Think Harder never goes below high.
- Chat search also matches titles, so an imported chat can be found by its near.ai title (`teemoon/Chat/Search/ChatListTitleSearch.swift`). Matched words are bold.
- `teemoon/Confidential/DisclosurePolicy.swift` decides how the date appears in the system prompt's `{{date}}` and in the web-search tool's "Today is":
  - Private destinations (this phone, a home machine, or a request sealed end to end) get the local day plus the zone's name and offset.
  - All other destinations get the day in UTC.
  - Either way it is the day, never the time.
- `teemoon/Views/Chat/StreamReveal.swift`: a streaming answer is shown "whole if quick".
  - A paragraph is held 600 ms, then revealed in steps. The answer's first paragraph is held 250 ms on cloud models and 0 ms on phone models.
  - A paragraph that appears whole fades in over 300 ms.
- `teemoon/Views/Motion.swift` defines the app's motion tokens: fade, paragraph fade, swap, spatial, playful and attention. Under Reduce Motion, sizes, glides and zooms turn into fades or hold still.
- The system prompt has its own settings screen (`teemoon/Views/Settings/SystemPromptRow.swift`).

## Changed

- **Composer.** The composer is one panel: photos, then text, then one row with "+", the where chip, web, and send.
  - "+" is its own glass circle outside the field. Send and "+" are filled 34 pt circles, and stop is a secondary circle. The panel has a 30 pt radius and a hairline edge.
  - The where chip shows only the model's name, not the place. Web hides for a model with no tools.
  - The transcript shows through the panel's Liquid Glass. The area around the bars is black.
  - Focus: the app asks the UIKit field for the keyboard through `ComposerFocus`. A send or the chats list drops it, and the field never takes the keyboard from under a presented sheet.
- **Text size.** Settings → appearance → size now steps relative to the phone's own text size, so Dynamic Type still works (`teemoon/Settings/Appearance.swift:232-273`). The old "large" setting is now "system".
  - Fixed font sizes across the app, the trust screens included, grow with the phone's setting. The where and web chips stop growing at xxxLarge.
- **Appearance.** The look is unchanged: dark only, as in 1.0.6 (`UIUserInterfaceStyle = Dark`). The light theme and the appearance mode setting were built during 1.1.0, then reverted before the cut.
- **Send gate.** The gate now produces one policy value, `sendPolicy`. The composer, retries and the Siri/Shortcuts intent all read it after `prepareTurn` (`teemoon/Confidential/ConfidentialSession+Verdict.swift:353-357`, `teemoon/Chat/ChatViewModel.swift:705-717`).
  - The chip and the gate read the same predicate: the chip shows `.hardBlock` exactly when the policy is `.block`.
  - Verdicts still in flight ask instead of allowing, and nothing leaves while the chip reads "verifying".
- **Consent.** A "send anyway" counts only for the attestation record and reason it answered. It is kept in memory and never persisted.
- **Wording.** The E2EE send question and the mobile-data question are now action sheets. "don't send" is visible, and "send unencrypted" is red.
- **Sealed requests.** Content given as an array is sealed whole, and any other content type refuses the send. Each request gets a fresh client key (`X-Client-Pub-Key`).
- **Where sheet.**
  - Browse lists, model info and Ollama's pull page now push inside the where sheet. Forms stay sheets.
  - On phones 667 pt tall or shorter, the where sheet opens large.
  - A near.ai model that is not end-to-end encrypted says so in its caption.
- **Model chip.** It shows the catalogue's name for the model.
- **near.ai tiers.** Before near.ai's tier list has been seen, no near.ai id counts as own-fleet. An unseen tier still goes through the attested gate and reads "verifying" until it is known.
- **Live catalogue.** An equipped model's capabilities follow its server's live list.
- **Prices.** Fireworks serverless list prices were refreshed on 2026-11-14 (`teemoon/Providers/Provider+Presets.swift`), adding `minimax-m3p1-flash` and `kimi-k3p1-pro`. `teemoon/Providers/ListPriceSnapshot.swift` was regenerated.
- **near.ai.** `z-ai/glm-5.3` is added to `KnownModel.nearAIAttestedThirdPartyIDs`, so it shows as "tee · third-party" before near.ai's live list loads.
- **Request details card.** The header's tokens never break mid-word, and its dividers are inset 12 pt on both sides.
- **README and ATTESTATION.**
  - `README.md` now says that a phone model sends web-search queries to Brave when web search is on, and describes images and the import.
  - `ATTESTATION.md` describes the running compose manager, the launcher index, and the limit of the measured env list.

- A row first drawn empty during a search round now draws its answer: a reply's cached parse is reused only while its text is unchanged.
- Fireworks:
  - A `deprecationDate` sent as `{day,month,year}` no longer fails the whole model list.
  - A Fireworks list saved by 1.0.6 is dropped once and fetched again.

- Reply and send races:
  - A stopped turn's late callbacks change nothing.
  - Only the latest turn clears the busy flag.
  - A re-verify retry runs only while its turn is still the chat's newest, and it names its chat.
  - "send anyway" after a still-checking question sends that question with its images, and leaves the newer draft in place.
  - Declining returns the question to the composer.
  - A Think Harder's new reply sorts after its restamped question.
- On-device engine (`teemoon/Inference/LiteRTToolBridge.swift`, LiteRTLM patch 9):
  - A tool call runs only from the current turn's own conversation. A decode the app abandoned can no longer run a web search under the next turn.
  - The cap and a drain timeout count as cut short, not as interruptions.
  - An engine that finishes after an eviction is ignored.
- Trust display:
  - A halted chain shows no unearned green, and the rail into a failing or unchecked step is grey.
  - Audit links appear only over what verified, and a tag-only audit page covers nothing.
  - An unreachable NVIDIA or TLS check is an orange "couldn't check" that keeps its own reason.
  - Malformed NVIDIA/TLS evidence, or an unreadable TLS certificate, blocks.
  - Intel PCS answering 400/404/422 to a request built from the quote blocks.
  - A record without GPU evidence clears the previous record's NVIDIA handle.
  - Image names wrap at `/` and `-` instead of truncating.
- The photo picker collects results on a serial queue, so results are no longer lost.
- Showing chats after an import opens the list without the last search.
- A new chat's title no longer slides on the first send.
- A share that arrives before teemoon is active raises the keyboard once.
- Pulling the attach sheet up no longer grows it to full screen.
- At accessibility text sizes, settings rows ("appearance", "places & keys"), the model browser and the trust sheet now fit without hyphenating or truncating.

## Security

Fixed in this release, as verified by the audit ("Prior claims re-verified" and "Findings"):

- **1.0.6 MEDIUM (gate), FIXED.** Under unpublished-only provenance, the send gate allowed a recipe-hash mismatch.
  - The exemption `unpublishedOnlyButE2EEIntact` now refuses on any hard failure, and it names `!modelComposeIntegrityFailed` and `lastRequestUsedE2EE != false` itself (`teemoon/Confidential/ConfidentialSession+Verdict.swift:287-289`).
  - Mutation checks I01/I02 are caught, by `SendGateRuleTests.everyVectorGivesItsPolicyAndAlert` only.
- **1.0.6 LOW (display), FIXED.** The chip read "verified" while verdicts were in flight (`:174`).
- **1.0.6 LOW (display), FIXED.** A previous record's provenance verdict was restored for a new record (`ConfidentialSession+Verifiers.swift:42-43`).
- **1.0.6 INFO (key binding), FIXED.** The key-binding checks now require a verified quote (`TEESignatureVerifier.swift:253-255`, `Verdict.swift:303-304`).
- **Build 61 LOW (disk), FIXED in 62.** The share inbox lacked protection and expiry.
- **Build 61 LOW (disk, found at runtime), FIXED in 62.** The update left the 1.0.6 store, which deletes did not reach.

Other security-relevant changes in this release:

- A sealed request that would ask for a plaintext reply field, or that would leave `chat/completions`, is not sent (`teemoon/Inference/HTTPTransport.swift:513-517`). `return_prompt_token_ids` and `return_meta_info` are among the refused names.
- On near.ai's attested models, image parts are sealed together with the text.
- A copied request details card masks every stored key and the provider's own auth header.
- When a reply is retried or replaced, its text is removed from the search index's WAL, the same as for a deleted chat.
- A turn that started attestable never leaves unsealed: it sends nothing and ends like a decline.

Open, as listed on the audit page:

- **MEDIUM (found after release, audit addendum 2026-11-19; mechanism present at 1.0.6).** Gate: only the first listed near.ai model enclave is verified, and every enclave near.ai's key service admits under the app id holds the same key (`teemoon/Confidential/AttestationService+Reports.swift:244-257`). A sealed message can be opened by enclaves the app did not verify, and the reply-signature check can't tell them apart. The message still goes only to near.ai, sealed. The trust screen's "sealed so only" and "lives inside" wording is not accurate as written. Work toward checking every listed enclave is in progress for 1.1.1.

- **LOW (accepted for 1.1.0, fixed in 1.1.1).** Gate: near.ai's model list can move a model the user was sending sealed to plain TLS with no ask. The tier comes from `owned_by` in an unauthenticated list (`teemoon/Providers/NearAIModelCatalog.swift:116`, `:129-134`). Not observed. The mechanism is present at 1.0.6.
- **LOW (accepted for 1.1.0, fix planned in 1.1.1).** Gate: a model key with no quote behind it gets the "still checking" ask with "send anyway", and an accepted turn is sealed to that key (`teemoon/Confidential/AttestationService+Model.swift:147-166`). Not seen on the fleet. The mechanism is present at 1.0.6.
- **LOW (carried, waived by the maintainer).** The user-edited system prompt is stored in UserDefaults (`teemoon/Settings/AppSettings.swift:28-32`).
- **INFO.** A source row in an imported chat opens any URL scheme on tap (`teemoon/Chat/Import/NearImportSource.swift:163-176`, `teemoon/Views/Chat/GroundingSourcesView.swift:101-104`).
- **INFO.** The launcher lookup can make about 400 Docker Hub requests on `URLSession.shared`, and `auth.docker.io` sets a `__cf_bm` cookie.
- **INFO.** The send-gate vector table `conformance/sendgate.json` is not in the public tree.
- **INFO (carried).** A truncated hash of a provider key names a saved model list, and that list is never removed (`teemoon/Providers/LiveCatalogStore.swift:220-223`).
- **INFO.** When the move back is in doubt, the stale 1.0.6 copy stays on disk. This affects build-61 TestFlight installs only.
- **INFO.** One store-move test is unreliable, and six behaviours are not pinned by a test (see Known issues).

The audit page labels findings by severity and title, not by number. Mutation IDs (I01–I13, S01–S13, B01–B07, A01) are the page's own.

## Known issues

- **Unreliable test.** `StoreLocationTests.aRealSwiftDataStoreMovesBackWithADeletionKept` failed in 5 of 12 runs on unchanged code.
  - Each failure takes the safe branch ("group store unreadable, opened in place"). The likely cause is the test's own seeding containers still holding the file.
  - The fix is planned for 1.1.2.
- **Six behaviours with no reliable test** (audit mutants S05, S09, S13, A01, B04, B05):
  - S05: the move order of a file set.
  - S09: the store configuration using the resolved URL. Only the update UI test covers it.
  - S13: a move that fails before the group store moved.
  - A01: the launch-time inbox purge.
  - B04: the inbox protection class, which a simulator can't read back.
  - B05: the date reset on a taken folder.
  - Also untested: build-61 mutants I05 and I06, an unpublished-only image together with a given-up tier or with an unsealed last request.
- **Launch is slower.** Time from launch to usable is up 22–31% against 1.0.6, in two runs on an iPhone 16 Pro:
  - 1.37 s → 1.79 s (+31%, n=5);
  - 1.57 s → 1.92 s (+22%). In this run, launch → composer first seen went from 1.27 s to 1.62 s.

  The maintainer accepted this for 1.1.0, and the cause is still open. The lead is the launch focus path (`teemoon/App/ContentView.swift`), which defers `becomeFirstResponder` on the UIKit composer (`teemoon/Views/Chat/ComposerTextView.swift`).
- **Cloud first hold.** The first paragraph of a cloud answer is held 250 ms (`StreamReveal.firstHoldMs`). The pacer never calls `finish()` when the stream ends, so a short reply that ends inside the hold is not shown at once. Both the `finish()` call and whether to keep the 250 ms hold are queued for 1.1.1, on both platforms.
- **Accepted LOWs.** The near.ai tier-demotion LOW and the key-with-no-quote LOW above are accepted for 1.1.0. Both are fixed in 1.1.1.
- **Not in the public tree.** `conformance/` and `docs/` are absent, so `SendGateRuleTests` and other tests that load vectors from those paths can't run from a public clone. In a public clone, the 1.0.6 MEDIUM fix is therefore pinned only by code review.
